# Threat model: OWASP Top 10 for LLM Applications (2025)

This page maps each OWASP risk to the control that covers it, the test that proves the control, and what
remains open. It covers the refund-capable support agent as built; production gaps are in
[production-architecture.md](production-architecture.md). Test names are pytest names under `tests/`, and
`adv-NN` are cases in `data/adversarial.json` (run by `run-scenarios`, with a safety gate of 0 wrong actions
and 0 leaks).

| Risk | Control in this system | Proven by | Open |
|---|---|---|---|
| **LLM01 Prompt injection** | Identity comes only from `SupportRequest`. Repositories are scoped to it (ADR-10). Policy never reads message text, except claims, which can only escalate. Tool results reach the model as `untrusted_data`. A strict tool allow-list applies, and arguments go through pydantic `extra=forbid` (ADR-4). Model text can state no money or outcome (ADR-11). | Scripted compromised-model tests: `test_extra_amount_argument_from_the_model_is_rejected`, `test_inflated_quantity_from_the_model_is_denied`, `test_two_proposals_in_one_turn_end_the_turn_without_a_proposal`, `test_model_text_announcing_an_unsupported_refund_is_blocked`, `test_model_fault_ends_in_a_safe_result`; adv-01, adv-02 (heuristic model) | Injection through seed data fields (item names) is wrapped but not tested with a real model. The heuristic mock cannot be injected, so the scripted tests stand in for a compromised model. |
| **LLM02 Sensitive information disclosure** | "Not yours" equals "not found". Tool results carry minimal fields (no name or email). The output check blocks foreign order IDs, emails and dates. Audit payloads are email-masked, and a blocked reply is stored only as a hash and a length. | `test_foreign_order_looks_exactly_like_a_missing_order`, `test_foreign_order_is_reported_as_not_found_and_never_refunded`, `test_injected_instructions_cannot_reach_another_customers_order`, `test_unsafe_model_text_is_blocked` (foreign-order, email, date cases), `test_a_blocked_reply_is_audited_as_a_hash_not_as_text`, `test_emails_are_masked_on_write`; harness invariant `no_foreign_data_in_replies`; adv-03, adv-04 | The output check does not block another customer's *name* (the model never receives one, because of scoping). The full customer message is kept in the audit (emails masked); there is no retention policy and no alert on order-ID probing. |
| **LLM03 Supply chain** | One pinned runtime dependency (pydantic). Dev tools are pinned. `pip-audit` (ADR-7) and a secret scan (`detect-secrets` plus credential patterns, transcripts included; ADR-14) run in `scripts.check`. Real keys come only from the environment (`.env` is git-ignored). | `scripts.check` steps "dependency audit" and "secret scan"; `test_an_unquoted_provider_key_is_found`, `test_transcripts_are_scanned_for_credentials` | No SBOM or hash-pinned lock file. Model-provider supply chain is out of scope (mock only). |
| **LLM04 Data and model poisoning** | No training, fine-tuning or retrieval corpus. Seed files are immutable, and runtime state is in memory and reset per run. | mock_env smoke test `test_seed_files_remain_unchanged` | Becomes relevant with RAG over help-centre content or feedback loops. |
| **LLM05 Improper output handling** | Model text is never trusted with money or outcomes. Code writes every amount and outcome sentence (ADR-11). The output check normalises text (NFKC, zero-width characters) and blocks amounts, outcome wording, foreign IDs, emails and dates. Tool-call JSON is validated before use. | `test_unsafe_model_text_is_blocked`, `test_model_text_announcing_an_unsupported_refund_is_blocked`, `test_invalid_arguments_are_faults`, `test_empty_model_reply_falls_back_to_a_safe_reply` | Pattern-based: novel phrasings of an outcome or amount may pass. Mitigated by code-written lines; a classifier is "Next". |
| **LLM06 Excessive agency** | No tool can move money: `request_refund` only proposes. Execution needs the customer's own next "yes" (single use, bound, re-checked; ADR-9), with an idempotency key and a lock. Policy rules cap per line, per order, cumulative threshold and customer cap (ADR-8). Human escalation applies above the limits. | `test_confirmation_executes_exactly_once`, `test_confirmation_is_bound_to_its_conversation`, `test_same_refund_confirmed_in_two_conversations_is_paid_once`, `test_two_proposals_in_one_turn_end_the_turn_without_a_proposal`, `test_threshold_counts_earlier_refunds_on_the_same_order`, `test_policy_limit_oracle_flags_refunds_above_the_threshold`; adv-05 to adv-08 | The affirmation word list stands in for a UI confirm button. No human-review workflow exists yet (escalations are records only). |
| **LLM07 System prompt leakage** | The system prompt (`support-agent/v1`) holds no secrets, IDs or limits. No control depends on it staying secret; every rule is enforced in code. | Design review: `prompts.py` contains guidance only; limits live in `config/policy.json` | No test for prompt disclosure. Disclosure is harmless by design. |
| **LLM08 Vector and embedding weaknesses** | Not applicable: no embeddings or vector store. | n/a | Relevant once retrieval is added (tenant isolation of the index). |
| **LLM09 Misinformation** | Replies state only what tool results contain. There are no delivery estimates (the records have no dates). Customer claims are compared with records, and a higher claim gets a code-written dispute line plus an escalation. | Scenario harness (scenario-01: no estimate; scenario-04: dispute and escalation), `test_dispute_line_quotes_the_disputing_claim_not_the_order_total`, `test_quoting_the_order_total_is_not_a_dispute` | A real model can still paraphrase wrongly within allowed facts. Needs eval runs with N samples (production doc). |
| **LLM10 Unbounded consumption** | The loop is bounded (4 model steps) and loop exhaustion escalates. A provider error or timeout ends the turn safely with a single result. One proposal per turn. | `test_model_fault_ends_in_a_safe_result[loop-exhaustion]`, `test_model_fault_ends_in_a_safe_result[provider-error]` | No per-customer rate limit, token budget or cost cap (designed in production-architecture.md, not built). |

**Traceability:** every audit record carries the trace ID, the prompt version, the policy version
(`config/policy.json`) and the model identifier, so each decision traces to the rules and model in force
(`test_every_audit_record_carries_prompt_policy_and_model_versions`).
